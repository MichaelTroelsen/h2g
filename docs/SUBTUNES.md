# Subtune census

Generated by `python/survey.py --subtune-census` (h2g 0.5.372), 95 file(s) under `C:\Users\mit\claude\c64server\SIDM2\SID\Hubbard_Rob`.

Every corpus file emits some number of subtunes and its PSID header declares
another. This is the difference, grouped by the reason for it.

It runs `_detect_tables` and `convert_tracks` -- the same two calls the
converter makes, with the same Detection -- and reads the census
`convert_tracks` fills in as it decides each subtune's fate. It is not a
second reading of the track table: the only thing skipped is pattern
conversion, which happens after every decision here is taken.

**The headline is mostly a negative result, and mostly the useful kind.** A
PSID header count is not a promise. The track table has no length field,
Hubbard rips routinely declare more subtunes than the table holds, and
reading past the end yields whatever bytes follow -- the converter is right
to drop that, and there is no music behind it. But not all of the loss below
is that kind: the player's own init dispatch (`sfx` in the table below, a
`CMP #imm / BCS / JMP` at the entry) names 97 subtune(s) across
8 file(s) as sound effects rather than music, which is a positive,
player-derived reason and not a garbage read past the table's end. That is
31% of the 316 lost below; the remaining 69% is
still read-past-the-end, as the old headline said of all of it.

**"Only 1 of 3 voice pointers resolve" is the trap.** It reads like a
partially recoverable subtune and it is not: it is a row past the end of the
table whose stray bytes happen to form one address that lands inside the
file. The pointer dumps below are what settle it. A real row is ordered and
close to its neighbours --

    Warhawk       0-8   $1847 $1897 $18FA $19B7 ... $1A0E $1A11 $1A14
    Warhawk       9     $6C16 $1840 $3C56      <- one "resolves"

-- and BMX_Kidz's subtune 1 "resolves" on `$B4FF`, which is subtune 0's own
voice 0. Neither is a subtune.

**And `refs`/`dangling` cannot tell them apart either.** Warhawk's subtune 9
reads 86 pattern references with *none* dangling, because a garbage pointer
into pattern or instrument data reads bytes that happen to be small numbers,
and a small number is a valid pattern index. A clean reference count is not
evidence of music.

The one file in this corpus that really did hide subtunes behind a readable
table was Powerplay Hockey, and they were behind a *second player* rather
than behind these pointers -- see H2G-CONVERSION-METHOD.md section 7.kkkkk
and `--engine`. That is the shape to look for; this is not.
